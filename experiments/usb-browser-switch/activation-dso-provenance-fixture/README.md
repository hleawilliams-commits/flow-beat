This separately versioned successor implements the reviewed [DSO provenance plan](../activation-dso-provenance-plan/README.md), building on the frozen [community claim/receipt fixture](../activation-claim-receipt-fixture/README.md). It adds fixed authored Linux shared objects and actual loader, constructor, descriptor, init and ordinary caller-address observations. It preserves the host process-image target/replacement definitions and strong aligned plain-pointer original slots. All live gates remain CLOSED.

The initial prepared source compiled five plain DSO objects and linked four DSOs cleanly. Before any host build or runtime, the ELF instruction-byte oracle refused because nonallocated debug sections with address zero were also considered candidate byte extents. The failed packet and all successful compiler outputs are retained. The narrowly corrected oracle requires an allocated executable section for its BLR-byte lookup. This does not change fixture C/assembly source or classify the original binaries as invalid. A second packet adopted the unchanged plain DSOs and passed the corrected ELF oracle, then compiled the four first-host objects cleanly. Its first host link refused unresolved counter definitions referenced by the frozen assembly; no fixture runtime or ASan build had started. The host harness successor supplies strong aligned four-slot target/replacement counter arrays, reports their actual values and computes the no-invocation total. The original assembly and DSO inputs remain unchanged. Both failures and their artifacts are retained. No runtime result is asserted by this README until a retained result and independent audit are linked below. Eight new selector groups and five exact controls are specified in [test-contract.json](test-contract.json). Passing predecessor matrices are not replayed.

## New exact controls

The contract fixes full expected failure lists before compilation:

- Substitute only the admission-used RA with a permanent host marker. The raw builtin RA and argument checks remain intact; the claim refuses before installation.
- Omit the one combined intended-object entry veto for the harmless dependency decision. Both paths stop before any entry, init or installer call.
- Ignore only an injected consumed-query failure while retaining the actual successful raw query/map. Both paths stop after the decision.
- Omit only the benign host constructor marker. The independent actual DSO-local count still records that constructor execution occurred.
- Omit authoritative handle bookkeeping while an explicit fixture-only safety hold retains the successful handle. This tests receipt loss without unloading, stale reads or a second lifecycle veto.

Crashes, timeouts, sanitizer diagnostics, invalid handles or inaccessible-memory reads are never accepted control outcomes. The emitted check names, exact failure set, process exit and raw evidence must agree; additional failures refuse the run.

## Limits and continuation

This fixture does not execute the production loader, approval/hash parser, firmware validation or manifest loading. Capability values remain authored. It does not prove arbitrary DSO/file/slot custody, safe unloading, arbitrary dependencies or interposition, native visibility, concurrent native invocation/publication, signal/nonlocal-exit behavior, anonymous-PC unwind, callback quiescence, external-writer coordination, general race/lifetime safety or recovery. Holding handles cannot explain those missing properties. No actual zero-base DSO case is promised.

Generated-only lookup remains separate from module-first fault attribution. A returned owner is not fault causation or proof of persisted blame. No runtime success authorizes observer composition or a core/community release. Preserve quarantine, official cores, packages and rollback; no reset, watchdog weakening or device operation occurs. Local Library row/provider/readiness/arguments and destructive/queued owner paths, stems staging, emulator topology/writer/stopped recovery and all other live gates remain closed. Preserve the x16 tail-transfer exception, x17/island unwind limits, opaque action x2 and register-only Source; no native pointee/post-return reads or cross-entry event pairing are added.
