# Consumed-validation refusal plan

This source-only plan defines one new ordinary owned-file boundary: genuine successful open and fd/name queries followed by an explicit consumed-validation veto. The native outcomes remain successful facts. The saved descriptor stays **HeldUnvalidated**, and the unchanged engine receives **{-2,7104}**, returning incomplete with no public payload. Every live gate remains **CLOSED**.

The [machine-readable plan](consumed-validation-plan.json) specifies seven future source groups, an independent raw-identity receipt, versioned report/observer changes and three exact controls. It reuses the [frozen witness](../activation-ordinary-file-fixture/README.md) and [failure-custody review](../activation-ordinary-file-failure-review/README.md). No predecessor matrix, retention or audit is replayed. This slice contains no new provider implementation, compiler or native-provider I/O.

## Exact boundary

The successor reserves one fixed receipt slot before OPEN, alongside the existing bounded journal capacities. A successful native int descriptor enters HeldUnvalidated before instrumentation or validation. Both original post-open identity queries run and must genuinely succeed. Their complete pairs, descriptors, flags and native identities are copied into a separate write-once raw receipt, together with the actual OPEN record and fixed directory/name binding. Its complete-last marker is an ordinary serial validity marker, not a second admission or a concurrent publication protocol.

Only after that receipt is complete does the explicit authored decision set evaluated/raw-valid/veto/consumed-valid to true/true/true/false. It refuses before setting creation_identity_available or promoting to VerifiedHeld. The expected FILE_VALIDATION diagnostic is accepted only with this exact decision and independently valid raw evidence. Failed native queries, mismatched identities and unrelated setup, capacity, argument or phase failures remain refused.

The original invalid-domain pair {-2,7104} reaches the synchronous callback caller. A prepared-return journal does not acknowledge private raw capture or authoritative recording. The unchanged engine rejects the OPEN value, and its actual return is AC_INCOMPLETE. The public observer exposes ActiveIncomplete with no payload; no private engine API is added.

After ordinary return, the witness freezes the provider report, independent receipt and consumed decision. It then makes one external cleanup request. Only known held custody permits its one native close. The raw cleanup outcome and custody remain distinct from the Boolean protocol result and public engine state. Any real returned close failure refuses this future case; no possibly closed token is probed, reused or retried.

## Report and observer custody

The new child envelope uses distinct pointer-free fields for the raw receipt, consumed decision, pre-cleanup provider projection and external cleanup. It has a new magic/version and measured target layout. The old 4,760-byte envelope is historical evidence, not the new ABI. The implementation must independently review actual sizes, offsets and conversions before runtime, including the retained four-byte nlink_t fact rather than guessing.

The envelope is written after cleanup and accepted only following normal child exit zero and exact report validation. It cannot acknowledge its own final write, and missing returns cannot reach this export. No abnormal-exit salvage is proposed.

The parent uses an explicit RAW_IDENTITY_AFTER_CONSUMED_VETO observation basis. It requires the independent receipt and absence of accepted creation; it never manufactures creation acceptance to bypass the refusal. It checks the receipt's expected directory/name and actual successful fd/name identities, then uses its own nofollow name query, observer descriptor, identity checks and bounded read. The file must be empty. Identity recheck precedes fixed-name unlink and removal of the empty owned directory. The child's saved descriptor is never a native-I/O capability in the parent.

This is separate stored evidence and a separate consumer, not adversarial memory isolation. Neither a valid receipt nor parent unlink establishes durability, release after an unknown close, or recovery.

## Finite future matrix

The proposed isolated GCC 7.5 Linux AArch64 C11 successor has four candidate selectors per mode: one ordinary consumed-veto selector and three dedicated control baselines. Three matching singleton controls add three children per mode. Plain and ASan/UBSan with leak detection enabled therefore specify **14 fresh exec children; zero executed here**. Each uses a fresh supervisor-owned disposable directory/file and one direct authored owner. No old direct-success, generated, frame, readonly or repeat selector is rerun.

Each supervisor evaluates all eight assertions—five shared safety/custody checks and three composites—after its child exits. The 14-child count does not count assertion hosts. Each baseline must pass all eight. Each control must fail exactly its named composite while the other seven pass. This is a future specification, not a claimed assertion result.

| Control | Exact authored change | Sole failing composite |
| --- | --- | --- |
| C1 query export | After the provider report is copied for export, change only queries[1].result.raw from 0 to -1. The actual records and independent receipt remain unchanged; the exported error fields intentionally remain false/zero. | validation-veto-preserves-native-query-evidence |
| C2 refusal domain | Supply OPEN raw -1 instead of -2, retaining error 7104 and the infrastructure origin. | validation-veto-remains-terminal-incomplete |
| C3 held cleanup | Skip only the eligible native-close body, recording requested/eligible true, attempted false, unentered result and HeldUnvalidated afterward. | held-validation-refusal-has-explicit-cleanup |

C1 owns every post-open projected-query fidelity/domain difference; shared safety uses the independent receipt. Its corrupt export cannot govern descriptor dispatch, path observation or cleanup. C2 owns the supplied pair and all resulting return/state/payload/event/failure differences: the unchanged engine instead completes with SELECTION plus OPEN -1/7104, selected owner and known_failure. It still performs no WRITE/SYNC/CLOSE callback and must retain external descriptor cleanup. C3 owns the missing close attempt/return and custody differences. Ordinary child exit may contain the still-held resource, but is never labeled an acknowledged cleanup.

Shared checks remain strict and mutation-neutral. Every cleanup record must truthfully bind its descriptor and HeldUnvalidated input: attempted, entered and returned agree; the attempted branch requires actual success and ClosedReturned, while the unattempted branch requires zero unused fields and HeldUnvalidated afterward. Attempted=true belongs solely to C3; unrelated native/report/observer/cleanup failures cannot be hidden inside a desired singleton result. The harness must not branch on control macros. Old helper assertions that universally require accepted creation, baseline completion or attempted cleanup must be partitioned explicitly rather than copied wholesale.

## Frozen boundary and excluded work

The exact engine/header, native leaf pair, six reader/type fragments, sole terminal admission and five setup-only functions remain unchanged. The provider table/context and authored request/model values remain stable through return. There is no second once guard, private inspection API, callback nesting, concurrent writer, DSO/installer or native frame adapter. The opaque unblamed boundary remains untouched and is not exercised in this focused matrix.

No CM_BLAME, CM_CRASHES, startup or quarantine policy is invoked. No actual close-error fabrication, missing-return experiment, signal/nonlocal exit, firmware/emulator/device, production or live composition is authorized. LL/SC retry, libc/canary/sanitizer dependencies, arbitrary custody/interposition, native visibility, quiescence and recovery remain unresolved. Ownership is not fault causation.

The later implementation must freeze and independently review the complete source ledger, exact reader/engine/leaf equality, new receipt and ABI, observer custody, finite selectors and three singleton controls before its first build. Retain every failed attempt and preserve all prior evidence. This plan itself authorizes no runtime work.
