# Fixed authored DSO provenance and custody plan

This source-only successor to the [offline claim/receipt composition](../activation-claim-receipt-fixture/README.md) at e9bcf3db860ea5e87607ccddc51faab334bf5da6 specifies how a separate Linux experiment could replace authored caller and loader facts with actual observations. No loader successor, production patch or live integration is implemented here. All live gates remain CLOSED.

The planned experiment keeps the existing process-image targets, replacements and strong aligned plain-pointer original slots. Fixed authored DSOs supply only real constructors, descriptor entry, init and SDK callers. Moving replacements or original storage into DSOs would create another custody boundary; that is deliberately outside this slice. A successful held DSO handle would establish the chosen fixture's code/data retention, not arbitrary module ownership or permission to unload.

[provenance-plan.json](provenance-plan.json) identifies fifteen reused source inputs, twenty-one source anchors, eight proposed transformation groups, eight future case groups and five safe controls. [retain-source.py](retain-source.py) retains that plan, this README, its own bytes and exact local inputs without child commands. [result.json](result.json) and [verification.json](verification.json) record retention and independent review when completed. Case names are specifications, not executed tests. Existing SDK captures, generated installers and passing matrices are reused as bytes and are not replayed.

## What the retained source establishes

The pinned SDK is 3e0c5cb010454228f4ee63226b60d060494eeaae. Its community.c:1804–1827 stores a successful dlopen handle and explicitly never closes it, then queries a link map, derives a range and resolves/calls the descriptor entry. Its own comment identifies constructor execution before dlopen returns. Descriptor refusal and failed init retain that handle; failed init also leaves previously installed hooks live. These are source facts, not new loader observations.

The selected range callback at community.c:1503–1523 matches a base to mutable scratch and computes a min/max PT_LOAD envelope. The earlier integration review identified the failed-query/zero-scratch counterexample. The successor must require successful handle/map/object provenance independently of numeric base. A valid zero base must remain representable, but this plan does not require forcing a real DSO to base zero or replaying the authored zero-base tests.

The completed composition's loader facts are booleans and copied authored segments. Its callbacks return cc_descriptor and receive fixture index/context arguments. Those are not the raw az_mod_v1 ABI. The retained header defines const az_mod_v1 *entry(void) and int init(const az_core_v1 *); the new adapter must use those types and state every transformation. Three selected helper bodies, the recursive cm → writer discipline, one-use session and receipt publication cut remain the existing foundation.

## Actual loader observations without expanding lifetime claims

Before calling dlopen, reserve fixed record, handle and diagnostic capacity and leave active session zero with neither cm nor writer held. Complete all fixed root and declared dependency loads before any descriptor entry/init session; reserve diagnostic space for the declared dependency constructors too. Only pinned authored files and one declared harmless dependency are in scope, inside the already pinned isolated Linux AArch64 environment. Every nonnull successful handle enters a pre-reserved permanent custody slot immediately, before dlinfo, symbol lookup or descriptor validation can fail. No later branch calls dlclose, resets the record or reopens its index. A failed dlopen has no successful handle to retain; it does not prove absence of code or dependency side effects.

The actual dlinfo return status and map pointer are separate facts. Clear and consume loader diagnostics around their exact calls, and copy diagnostic text before another loader call can replace it; errno is not a substitute. Copy program-header values while the iterator callback owns them. The future adapter must match the held object using the actual map, base, checked program-header/dynamic metadata and exact pinned ELF identities, with a unique accepted candidate. A pathname, equal base, RTLD_LOCAL or nonnull dlsym result alone does not supply that relationship.

For selected symbols, compare the returned address and its owning link map with the held intended object and exact fixed ELF symbol value/type/extent. A declared dependency exporting the entry name is a new refusal case: actual resolution is observed, but the isolated decision probe invokes neither candidate nor control entry. Reject unsupported symbol forms or ambiguous ownership before invoking code. Exact libc API availability, signatures and compiled call paths remain future preparation checks against the pinned Linux toolchain; no libc implementation or loader behavior has been executed or proved by this document.

Private checked PT_LOAD scratch supplies both individual segment extents and the retained min/max envelope. Publish each copied immutable module record once at its original fixed index, before descriptor entry; failures leave indexed holes. Keep the SDK caller predicate's min/max envelope semantics, including gaps and non-executable regions. Use separate complete owned readable/extents checks before descriptor data reads, rather than treating that caller envelope as readable memory. Actual main-image executable headers supply the target envelope with checked arithmetic, while the stronger fixed target16 custody and overlap rules remain.

These checks assume fixed authored data, no concurrent unload or mprotect, and no competing mutation of descriptors. Segment flags and arithmetic cannot establish general readability, immutability or data-race freedom. Arbitrary interposition, dependencies, malicious libraries and path-to-file races remain outside the contract. Read-only mounts and pinned artifact checks narrow this controlled experiment; they do not authenticate an arbitrary loader.

## Real entry, init and caller address

Use the exact retained azmod-mod.h types. The permanent az_core_v1 table has the actual ABI and size, a populated claim_hook field and explicit NULLs for unavailable services. A separately named fixture-only host export, const dp_fixture_input *dp_fixture_input_get(unsigned fixed_index), returns read-only process-lifetime records containing the exact existing host binding arguments. Retain its fixed signature, host symbol identity and returned record identities. Authored DSO init calls it before its direct SDK call; it is not an added SDK service or an unverified setter. Do not move those host original/replacement objects or substitute temporary pointers.

A fixed authored assembly stub in the DSO calls the ordinary SDK-signature entry through the table's claim_hook pointer using BLR, with a retained symbol at the immediately following instruction. The ordinary noinline entry captures builtin caller RA and one acquire session value before dispatch. The relocated marker supplies an independent exact RA oracle, supplemented by actual owned executable segment membership and retained disassembly. No authored-RA entry, TLS override, helper-frame capture or tail-call assumption is used. Diagnostic copies distinguish the raw capture from the admission-used value and retain actual arguments/result after the worker returns. Executable membership is always checked against raw capture; only the admission equality oracle uses the controlled admission-used value.

Before reading a returned descriptor, require full bounded owned readable coverage of its fixed authored storage. Apply the same discipline to the ID, tag pointer array and bounded strings; inspect the bound before each array access. Check init as the exact owned executable symbol before calling it. The source's minimum descriptor-size and ABI/id/tag predicates remain, with explicit stronger fixture custody. A nonnull descriptor or an ABI integer is insufficient to dereference arbitrary storage.

Actual descriptor entry runs after module range publication while session remains zero. Open the existing one-use session only after descriptor acceptance, then call actual init outside both locks. Close under cm → writer after ordinary return, preserving already-admitted claims and accounting. Returned warning success remains SDK0, and failed init retains handles, originals, emitted code, metadata, receipts and count. Callback closure supplies no quiescence or reclamation. Retain terminal incomplete/unknown outcomes rather than inventing recovery for nonlocal exits.

The constructor has a bounded benign host diagnostic marker and an independent DSO-local count. The marker grants no claim capability. Its observed order should be constructor, dlopen return, range publication, entry, session open, init, close. This establishes only the tested observations; it does not contain constructor side effects or prevent constructor-started work. A selected read-only callback probe can complete on another thread to establish that the two admission locks are released during actual entry/init.

## New cases and controls only

The future groups cover an actual ordinary DSO claim, constructor/order observations, a dependency-owned entry decision, an injected consumed-query failure, descriptor-refusal custody, partial failed init, a foreign DSO caller using an active module's ID, and exact symbol/data ownership. The foreign caller must be exercised while the named module's init session is open so closed-session refusal cannot mask the caller check. No patched target or replacement is invoked. There is no reason to repeat scalar forwarding, return-channel, exception, CFI or old policy matrices.

Five proposed controls have exact intended failure lists in the machine plan:

- Replace only the admission-used RA with a known permanent host marker, retaining the true raw builtin capture. The control refuses before installing.
- Omit the new same-object entry veto in a dry decision using an actual harmless dependency symbol. Both variants stop before any call.
- Ignore a declared post-call consumed-query failure while preserving the actual successful raw query and valid map. This is an injected consumption failure, not an observed dlinfo failure.
- Omit only the benign constructor marker; the independent actual local counter still proves that this constructor ran. This detects missing observation, not constructor prevention.
- Omit only authoritative handle bookkeeping after success and later descriptor refusal, while an explicit fixture-only safety hold retains the handle. This tests receipt loss, not unloading or use-after-free.

Freeze the final source transformation ledger, test contract and complete expected failure sets before compilation. The entry-owner control removes one combined intended-map/symbol/extent predicate; raw type/coverage of the actual harmless dependency remains valid outside that predicate, with no earlier or later equivalent same-root veto. The custody control proceeds through its separately declared safety hold without treating an empty authoritative record as another lifecycle veto. Each decision control must have every other prerequisite valid and no hidden duplicate veto. A masked control is a test-contract defect to fix before execution, not a reason to weaken policy. Crashes, invalid handles, stale reads, unmaps, races, timeouts or sanitizer failures are not acceptable control successes.

All raw addresses, loader diagnostics, paths, source captures, binaries and execution logs remain private. Publish only allowlisted evidence and hashes. The planned actual loader and ABI work remains separately reviewed from retained-byte auditing; a byte audit is not a runtime test.

All native caller/SDK ownership, nonparticipating writer, signal/nonlocal-exit, interrupted-PC unwind, native visibility, callback quiescence, topology/recovery, Local Library activation and stems gates remain closed. Ownership is not fault causation. No emulator/deck, official core, package, catalog or release action is part of this plan.
