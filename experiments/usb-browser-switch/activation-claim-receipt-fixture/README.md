# Offline community claim and owned receipt composition

This separately versioned Linux AArch64 experiment implements the [source-only composition plan](../activation-claim-receipt-plan/README.md) using authored loader, capability and caller-address inputs. It composes selected SDK inline-claim predicates with the [owned installer receipt successor](../activation-installer-receipt-fixture/README.md). It does not load community libraries, install a production core, attach an observer or execute firmware. All unresolved live gates remain CLOSED.

The first reviewed matrix passed in plain and ASan/UBSan configurations. Eleven new selectors passed 64 summed named assertions per mode, and all six compiled negative controls produced exactly their expected failures. The [sanitized result](result.json) records this execution; the [composition ledger](composition-ledger.json) identifies exact copies, extracted helpers and authored replacements. The independent [retained-byte audit](verification.json) passed on its first invocation, reconstructing exact source and ledger bytes, all command receipts and named reports, the closed packet inventory, linked ELF and emitted-route bytes, and the sanitized public projection. It did not execute the runner, composer, compiler or binaries. No earlier matrix or installer transformer was replayed.

## The composition boundary

The new composer consumes already retained community.c, receipt.c/receipt.h and the generated installer/protection files. It preserves the exact cm_id_ok, cm_find and cm_called_by function bodies and explicitly transforms receipt types and orchestration. The resulting source, complete diffs and ledger remain in each private packet. The earlier generated installer and protection files are copied byte for byte; this checkpoint does not regenerate their instrumentation or silently describe the new admission layer as unchanged SDK code.

One recursive community mutex precedes one nonrecursive common writer mutex and the existing protection helper. Direct Core claims use writer then protection. The private receipt operation starts with writer already held; it does not call the old public receipt wrapper or retain its independent community mutex, epoch or module_hooks counter. There is no writer-to-community lock edge.

The real SDK-signature entry captures the builtin caller address once and acquire-loads one active-session handle. That ordinary configuration is compiled separately. Executed fixtures use a separately named authored-address entry and explicit loader/capability values; they do not authenticate real callers or validate actual dlopen, link-map enumeration, manifest parsing or approval.

The fixed session handle is zero when closed or index+1 for an immutable one-use module session. Session storage is never reused or reopened. The locked worker checks captured nonzero/current/index agreement as one veto after the retained ID, caller-envelope, init/loading, hooks_ok and target-start predicates. A delayed call cannot adopt a newly opened session. An admitted claim keeps the shared locks through its receipt and SDK accounting; close waits for that accounting. Entry and init callbacks run outside both locks.

All owned module/receipt IDs have 33 bytes, preserving the SDK boundary of 32 characters plus NUL. Fixed target, replacement and original-slot identities are checked separately from claimant-envelope policy. Inline claim does not require its replacement address to lie inside the caller's module envelope; the old receipt fixture's additional proxy is removed here. The min/max PT_LOAD caller envelope still includes gaps and non-executable segments. No frame-thread, thread-identity, LOADED-state or vtable-hook predicate is imported into inline claim.

## What remains owned

The four fixed bindings use three distinct bound process-image targets: binding 3 aliases target 0. Each binding has its own authored replacement and strongly defined aligned plain original slot; these objects retain process lifetime. A supplied slot identity is compared with the known descriptor before dereferencing it. This is bounded custody for these objects, not a general guarantee for arbitrary SDK pointers or unloadable libraries.

The shared ledger reserves target16, binding, receipt, metadata and count capacity before allocation/protection operations. Actual emitted mappings, separate island/target protection tokens, raw returns, saved errno, uncertain cleanup and burned slots remain in the inherited receipt representation. Immutable committed module views provide storage exclusions without requiring Core to read mutable community records.

The existing lexical cut remains metadata publication, actual original-slot store, then actual target redirect. New admission/custody/session decisions finish before target unlock. A normal returned redirect receipt increments the selected authored module snapshot's nhooks field exactly once before releasing locks, including a relock warning. SDK success 0, raw installer success 1 and richer receipt statuses remain separate. Later failed init retains code, originals, metadata, receipts and nhooks; clearing a callback field does not cancel work or reclaim code. An unexpected publication/result mismatch remains incomplete evidence rather than a safe retry or teardown instruction.

## Focused validation interface

[run-tests.py](run-tests.py) creates a new ignored private UUID packet and executes only the new reviewed selectors and controls. It snapshots the new source/contract, retained composition inputs, fixed assembly and serializer reference, and the frozen plan. The reference test source is never compiled or executed. Selective sections/selectors permit a reviewed continuation without replaying already passing cases after a local preparation or parser failure.

The matrix used GCC 7.5.0 (Ubuntu/Linaro), target aarch64-linux-gnu, in the pinned Linux ARM64 image sha256:c7e3893c4f03e0ff30555c2120b3d9ec53834eaa2c8ce376a2da09b70fd23a90. Named containers use no network, pull-never, a read-only root and source mounts, and a private writable output directory. Plain and ASan/UBSan configurations are separate; leak detection is enabled. This does not prove arbitrary mapping-leak freedom, concurrent signal behavior or the actual SDK runtime's mutex/loader integration.

The ordinary builtin-RA configuration is compile-only. Runtime builds enable the declared authored-ingress and scheduling seams. Each process must emit the exact ordered named-check report with no unexpected stderr and a bounded raw evidence file. Negative controls require their complete reviewed failure lists and ordinary cleanup, rather than crashes, hangs or sanitizer failures. Object and executable inspection checks AArch64 identity and strong aligned original-slot definitions. Disassembly is retained for review, not promoted to general instruction-fetch or signal proof.

Every attempt retains commands, environment, outputs, exits, source/generated files and partial artifacts. Public results contain allowlisted summaries and hashes; raw addresses, command lines, mappings and binaries stay private. Source review, runtime assertions and retained-byte auditing are distinct evidence.

The first invocation completed 43 compiles, 14 links and 34 fresh-process executions: eleven candidate selectors and six controls in each of two modes. The standalone ordinary configuration accounts for one compile and was not linked or executed. There were no failed compilation stages, unexpected runtime outcomes or sanitizer diagnostics. The 64 summed candidate assertions use 54 distinct names; the common no-patched-target-invocation assertion appears in multiple selectors.

The packet retains 15 captured inputs, nine composed outputs, 151 command receipts, 302 primary output streams and 190 work artifacts. Its 822-file count includes the private result and excludes the subsequently added sanitized copy; the complete packet has 823 files. These counts describe retention boundaries, not additional tests.

Six separately compiled controls omit the combined pre-open session veto, omit SDK accounting, map a published warning to refusal, erase the failed-init count, bypass hooks_ok, or truncate the copied 32-character ID. Every control exited 1 with precisely its reviewed named failures, in counts 3, 1, 1, 1, 3 and 1 respectively, and no unexpected stderr. Candidate processes exited 0. Both modes retained all four target and replacement hit counters at zero.

The pre-open control removes the complete new session veto while preserving the older loading predicates, so the otherwise valid same-module request can expose that missing guard. The count and warning controls retain code and custody. The ID control corrupts invisible copied metadata only. Threaded oracles use an observed mutex refusal or explicit callback completion, release/join all actors before final assertions, and do not infer successful publication from elapsed time alone.

The admitted-close schedule observed a real busy community mutex after target redirect and before SDK accounting, then released and joined the claim before confirming close retained count 1. The writer-busy counter remained zero; this is not a separate writer-contention test. Core-conflict installed Core first and then refused a Community alias sequentially, without a concurrent Core writer. The loader-inputs case retained invalid range slots 0–2 and accepted entry/init lifecycle at valid base zero in slot 3, with no claim there; it does not exercise cm_find/claim across those holes.

## Remaining limits

The loader tuple, module ranges, capability values and caller addresses are authored. No actual community loader, DSO constructors, approval parser, firmware, endpoint or physical device is exercised. The selected exact SDK helpers do not make all community.c behavior part of the fixture. Generated-only lookup remains separate from module-first fault attribution.

No old scalar forwarding, return-channel, exception or CFI scenarios were repeated. No patched target or replacement was invoked in this matrix; an ordinary later call would not prove instruction-fetch visibility. Signal interruption, forced exits, nonlocal jumps, arbitrary interposition, other writers, anonymous-PC unwind, general callback quiescence and production recovery remain outside this checkpoint. Ownership is not fault causation, and these results cannot justify quarantine or native activation.

The next proposed step is a source-only plan for a separate offline Linux fixture with fixed authored DSOs: actual builtin caller addresses and actual handle, link-map, PT_LOAD, entry and init observations. That plan must distinguish constructors running before admission, retain every successful load handle even if later provenance or init fails, and specify exact source transformations before implementation. It would address the current authored-input boundary without claiming arbitrary-DSO custody, live integration or a replay of these passing cases. No such loader successor is implemented here.
