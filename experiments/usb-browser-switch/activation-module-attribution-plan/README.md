# Immutable module and generated-range attribution plan

This source-only successor specifies an offline C/Linux composition of actual fixed authored-DSO module observations, the retained generated instruction reader, and the exact SDK PC/LR/frame consumer. It adds no executable composition, production registry, installed handler or live observer. Every existing runtime, activation, staging and recovery gate remains **CLOSED**.

The [machine plan](composition-plan.json) defines eight transformation groups, ten future case groups and eight safe controls. These are specifications, not executed tests. The starting branch checkpoint is f2cbeb2fb4394c5a79854c84d9d70f4bd812e721. Existing sources, both DSO configuration failures and successful matrices remain frozen. The source list reuses nineteen local retained inputs; no new SDK source capture is needed.

## What must change

The current DSO fixture's plain `range_published` flag and mutable `g_cm_n` are protected by cm → writer. Its diagnostic snapshot takes both locks. Neither is suitable for a nonwaiting attribution reader. The new design uses four fixed, permanently retained immutable module payloads, each with its own one-way release publication flag. An acquire scan skips unpublished holes and reads copied 33-byte IDs and checked envelopes only after publication. It never consults mutable lifecycle fields or the loader.

A module payload needs successful **consumed** provenance, permanent handle custody, a fixed independently assigned identity/index and checked bounds. Raw query success or a nonnull held handle is insufficient. Only the A/B roots have Community identities. The rootstub and dependency remain held and observed without inheriting another module's ID. Process identity 100+index and the IDs are authored fixture inputs, not signed manifest execution or actual OS process observations.

Positive ownership publication precedes entry and descriptor validation. It is independent of hook permission: the frozen core currently suppresses its range field on the hooks/firmware-any refusal branch, so the successor must add a separate fault payload before that lifecycle refusal while preserving every admission predicate. The private writer's known-module storage exclusions use this same committed table. Descriptor/partial-init refusal must never clear ownership. Handle, original, replacement and generated-code custody remain permanent.

## Exact consumer and new adapter

The retained SDK names are `cm_owner_of` and `cm_blame_fault`. The new `ma_owner_index` adapter first scans immutable module envelopes in original index order; only after a miss does it call unchanged C `rc_lookup`. Generated Community identity must resolve by full copied process identity and all 33 ID bytes to exactly one committed module slot. Core, missing and ambiguous identities return -1 and preserve LR/frame fallback.

The exact 962-byte `cm_blame_fault` body stays byte-identical. Narrow lexical aliases select the new index adapter, the permanent module array and explicit modeled frame/file dependencies. The unchanged ID expressions then reference process-lifetime copied storage. Returning an ID pointer from the temporary `rc_metadata` copy would be invalid; the index bridge avoids that.

Module-first applies at **each address**. Generated Community PC can therefore beat module LR. Core PC is not a fabricated community blame ID. The original PC → LR → at most sixteen frames, read short circuit, address guards, nonincreasing-frame ordering, volatile once guard and persistence-call sequence remain exact. The crash reporter's separate forty-frame printing loop is only a source reference. No handler installation, native frame read or real blame-file I/O is proposed.

## Visibility limits

All fixed loads run before any module publication. Constructors execute inside dlopen before successful handle return and provenance discovery; their lookups are unowned at that time. Later publication cannot retroactively attribute a constructor fault. Successful handles with provenance refusal remain held but invisible. Descriptor/init refusal after positive publication has the opposite retention behavior. These are distinct stages.

Independent per-slot acquire loads do not form one coherent snapshot. An earlier index that commits after the reader passes it can be missed in favor of a later visible index or generated record. First-index precedence is over the entries observed committed by that scan; a later call may differ. Do not add retry/wait or claim linearizable whole-registry selection.

A later module envelope may mask an existing generated instruction or cover a literal address. The current actual loader closes registration before entry, so overlap/later-mask tests belong to a separately labeled synthetic policy path. They do not demonstrate actual DSO overlap or late-loader publication. Min/max envelopes intentionally include PT_LOAD gaps and non-executable segments and do not establish readable memory.

## Review and future validation

The plan binds precise line-byte anchors to the nineteen reused inputs. The retention helper copies only these pinned sources plus this README, the plan and itself into a fresh private directory; it executes no child commands. The separate result and verification files record this source-only evidence when available. Audit structural assertions are not runtime case counts.

Before a future first build, freeze and independently review its complete transformation ledger and exact control failure sets. Keep actual fixed-DSO selectors distinct from model-only publication/identity cases. Keep the frozen receipt cut, ordinary warning/accounting behavior and all target/replacement invocation counters at zero. Codegen ordering controls, if needed, are compiled only. Retain failures and exact test bytes; do not replay old passing scalar/ABI/exception or attribution matrices.

No arbitrary DSO/slot lifetime, approval execution, interposition, nonparticipating-writer coordination, concurrent native invocation/publication, signal/nonlocal-exit safety, anonymous unwind, callback quiescence or general recovery proof follows. Ownership is not fault causation or durable blame. Quarantine and official protections remain unchanged.

The next bounded step is a separately versioned offline implementation of this reviewed composition. Live image/current-hook provenance, application/supervisor/QEMU writer and stopped-recovery evidence, and Local Library row/provider/readiness/arguments/owner scope remain separate gates.
