# Terminal attempt and immutable attribution composition plan

This is a source-only plan for a separately named `activation-attempt-attribution-fixture`. It composes the retained terminal attempt with immutable module/generated-range readers using authored values. **Every live gate remains CLOSED.** No implementation, compiler, loader, installer, runtime matrix, firmware emulator, device action, production integration or live observer is part of this review.

The baseline is development commit `ffa804c2d1c919ac88bbe5edef449b680106d72c`; retained SDK sources originated at `3e0c5cb010454228f4ee63226b60d060494eeaae`. [composition-plan.json](composition-plan.json) is the machine-readable specification. Sixteen reused local inputs plus this plan, README and retention helper form nineteen inputs; twenty-five line-byte anchors identify the source cuts. The eight transformation groups, nine future case groups and eight exact safe controls are **planned, not executed**.

## One admission before selection

The new `ac_run` and fixture entry retain one process-lifetime attempt state and its existing strong CAS. A request supplies authored PC/LR/FP and I/O values, not an already resolved owner. The CAS winner alone may read request fields, initialize selection, call readers or frame providers and advance receipts. A losing request returns Suppressed without doing any of that work or reading incomplete payloads. The wrapper must not first admit and then call the old `fa_run`, which would create a second admission.

A separately authored `ac_select_values` replaces the old resolved-selection source at the selection receive cut. It does not call, include as executable code, modify or wrap `cm_blame_fault`, `ma_blame_fault` or `ma_consume_fault`. The pinned volatile-guard consumer is a policy reference only. Its guard and all predecessor sources remain unchanged.

The selection cursor belongs to the admitted attempt. Each fixture step performs one complete reader or authored cell operation, then may return Pending to the serial driver while the selection event remains Entered. Ordinary mode drives the same cursor synchronously to a value or explicit invariant error. Pending does not record a return, supply another admission authority, suspend a native callback stack or execute a nonlocal exit. No fixture seam runs inside a frozen reader. Repeated Pending steps leave raw availability false and do not increment the selection-return sequence; one ReturnedValue advances it once. An invariant error has a separate private returned-error diagnostic and supplies no successful raw selection.

## Exact identity and independent visibility

The retained `ma_owner_index` checks module envelopes in slot order before generated instruction ranges at each address. The new policy tries PC, then LR, then at most sixteen authored frame pairs. Integer-keyed cells supply modeled exact eight-byte reads: next FP first, then RA; a missing/short read ends fallback. RA ownership is checked before rejecting a nonincreasing next FP. The new model additionally checks FP+8 overflow before either cell read; that is not an established check in the frozen consumer.

The reader returns an index or -1; it does not expose whether a negative result meant Core, absent, unresolved or ambiguous generated ownership. Those negative results permit fallback. A generated Community owner at PC can precede another module at LR. No-owner exhaustion yields a zeroed NoCommunity value and exactly one opaque authored unblamed operation. It consumes the first attempt permanently, even if later publication would produce an owner. No live-mod flag, clock, append operation or quarantine logic is modeled by that opaque operation.

The first nonnegative index ends address selection. Snapshot exactly that permanent module slot once, then copy its index, all 64 process-identity bits and all 33 canonical ID bytes into the raw latch. Generated metadata binding numbers are not module indices. The authoritative receipt copies the raw value, and completion copies the working value. Neither recording nor I/O nor completion resolves the address again. An invalid index, unsuccessful exact-slot snapshot or invalid tuple is an explicitly returned adapter invariant error: retain a private diagnostic and remain ActiveIncomplete. It is neither NoCommunity nor a return that never occurred. The dedicated future snapshot-error case first preserves the actual successful reader result and copied tuple, then substitutes only consumed success=false at a declared fixture boundary. It does not demonstrate an actual reader failure or alter published storage.

Four fixed module slots and four generated records use independent one-way release/acquire publication with immutable payloads. A skipped hole may become visible to a later query; earlier PC queries are not restarted. A later lower-index envelope may mask an address for future queries while an already chosen index and copied tuple stay unchanged. These reads are not a coherent registry snapshot. Model setup uses bounded authored canonical-ID validation (1–32 ASCII characters from [A-Za-z0-9._-], followed by NUL and zero padding) and does not invoke SDK validation, a loader or an installer.

## Private receipts and future witnesses

Public observation preserves the existing rule: state only until OrdinaryReturned, then an acquire-gated immutable completed result. Raw selection, intermediate traversal, returned errors and working receipts remain private. Serial stopped inspection is separate from the public API. A selector trace bounds eighteen address probes, thirty-two cell reads and one successful-slot snapshot without consuming the six attempt event slots.

The future witnesses focus on the composition: admission suppressing actual reader work; generated binding zero resolving module three; full process/ID copying; generated-PC precedence and Core fallback; publication between complete queries; masking between index resolution and exact-slot snapshot; immutable positive and negative raw results; composed fd-zero/failure continuation; selected stopped cuts; and later diagnostic lookup that cannot reopen or change the attempt. The older I/O matrix and reader matrices are not replay targets.

Each control has a dedicated fresh selector with exactly one declared semantic failure, plus mandatory infrastructure checks. Controls move selection before admission, introduce a second admission, mistake binding for module index, narrow the copied process identity, reselect at recording, stop on Core PC, refresh a negative selection, or expose the raw selection publicly. Live storage and authored providers keep those controls safe. Crashes, sanitizer errors, timeouts and extra failures are refused as control evidence. The complete mutation and nonmasking requirements are in the plan.

## Retention and limits

`retain-source.py` copies only declared pinned local files with nofollow regular-file reads, exclusive output creation, a closed inventory and line-byte hashes. It refuses an existing result and runs no child commands. Its only changes from the retained predecessor helper are four literal scope/name substitutions. The first retention and an independent byte audit must bind the exact final plan and README; audit assertion counts are structural checks, never runtime cases. The audit source must be copied before invocation and remain unchanged afterward.

No prior passing matrix, source capture or audit needs unchanged replay. The retained attempt compiler lowered its single logical CAS to LDAXR/STLXR with an exclusive-monitor retry loop; no bounded or wait-free machine admission is established. Normal attempt dependencies include memcpy/memset; the retained readers include memcmp/memcpy and a separately classified stack-canary failure edge. Successor codegen needs its own review if later built; this plan supplies no transitive libc, canary-failure or signal-safety proof.

Frame and file providers remain authored. Actual DSO/installer/approval invocation, arbitrary slot or DSO custody, loader/interposition, nonparticipating writers, concurrent/native publication or invocation, handlers, signals, nonlocal exits, native frame/crash persistence, visibility, callback quiescence and recovery remain deferred. Quarantine, protections, all old failure packets, frozen consumers/readers/receipt cuts, original/replacement custody requirements and live-observer restrictions remain unchanged. Ownership is distinct from fault causation.

After the source/control reviews and first retention audit, a later separately versioned offline implementation may be considered against this exact plan. It must freeze and independently review its transformation ledger, exact reader extraction, provider seams, cases and controls before a first build. This plan does not authorize production or live composition.
