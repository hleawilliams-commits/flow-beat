This retained pre-run plan is not runtime evidence. The subsequent
[completed run and restoration](runtime-evidence.md) are recorded separately. The previous [route observer](../route-observer/)
captured one off-thread record and deliberately skipped three. This candidate
changes that capture limit while keeping the same native entry and scalar ABI.
It must pass its own host/concurrency controls, exact binding and ARM64 validation
before any installation. Preserve the earlier experiment and its restoration
receipts; never reuse its backup as the new baseline.

Use only the already configured localhost emulator. Root owns runtime actions;
other agents perform offline review. Take a fresh backup of the current files,
modes, inventories, loaded mods, settings, cores, caches and absent paths. Refuse
pre-existing state for this new module identity, an occupied/in-use emulator,
unexpected process changes or unrelated file drift. Install only this observer
and its explicit opt-in, through the unchanged SDK claim service. Require its
exact loaded row, positive ready message and one accepted hook; no retries,
policy weakening or takeover if refused. Keep both existing cores untouched.

Before sending input, inspect the first RAW record and current own-module
diagnostics. Native attempted/claimed counts must still be zero, capture live,
and RAW baseline valid. The saved host-driver counter may differ after restart.
Preserve its exact bytes/mode and align the host file to that observed baseline
without sending a guest frame. Verify completion before using the driver. Do not
hard-code the earlier 133/128 values as current facts.

Reach the empty Waveform view with the bounded native BROWSE sequence and inspect
the screenshot. In the same process send two clockwise detents, sample status,
then two counterclockwise detents and sample again. Record the current host-file
counter separately from RAW byte 34 and the native `w3`/`w4` bits. Check each
stage's current liveness, attempts, reservations, capacity/contention losses,
native/RAW gates and queue losses. Keep original TID, x0/x1/x2 and LR copies
private; publish only useful scalar values and explicitly scoped equality or
exact-firmware code-location findings. No native pointer dereference, return-side
reader, LOAD, playback or input suppression is part of this run.

Slots can be consumed by unrelated earlier entries. A reservation count is not
proof of publication, consumption or durable logging. The worker can skip a
WRITING hole, and later slots can be printed first. Compare complete records by
their explicit reservation IDs; never convert those IDs into native/global
event order. Even a matching four-record sequence does not establish final
delivery, active child identity, native owner thread, successful queueing,
completion, cancellation or retained lifetime. Stop on missing evidence or
unexpected state instead of repeating inputs automatically.

Remove only this run's files, opt-in and registration changes. Verify the fresh
baseline after a clean empty restart, natural startup-guard expiry, probe
unmapping and opt-in absence. Restore the original host counter bytes/mode
without guest input. Guest and host restoration have separate receipts so a
host-only retry cannot repeat guest cleanup. Preserve partial failures privately,
publish a sanitized result only after inspecting it, and release the emulator.
Hardware timing, first-use TLS costs and the earlier stems staging gate remain
outside this experiment.
