# Direct core-owned Mod Menu request: source design

Status: design only. No implementation, build, emulator run or device access accompanies this note. It does not identify the cause of the physical MODS tap failure. Production MODS Shortcut 0.1.1 is unchanged.

All source links below refer to upstream commit `3e0c5cb010454228f4ee63226b60d060494eeaae` (core 1.2.3). The inspected `src/azmod` files match that commit.

## Feasibility and boundary

**Opening the core's own menu over the waveform view is feasible at the source-design level without sending SOURCE.** The menu is already an independent override-redirect X window owned by the overlay thread: [window creation](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/mod_menu_overlay.c#L693-L729), [placement](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/mod_menu_overlay.c#L2197-L2245), and [thread loop](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/mod_menu_overlay.c#L2506-L2534). Painting and touch dispatch do not require a native SOURCE frame. A UI-thread request can therefore make progress when no mixer frame arrives.

However, the existing full-menu layout is selected by `g_docked && menu_focused`, and “docked” currently also means ownership of the native SOURCE row. Simply setting those flags would be incorrect. With `want == 0`, [ov_docked_gate](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/mod_menu_overlay.c#L1540-L1578) closes it immediately; faking `want` would still fail the SOURCE visibility test and corrupt the native selection contract.

This would be a separate upstream core and SDK change. It is not possible through a new community package alone. No firmware navigation call or additional private address is proposed.

## Narrow proposed service

A proposed append-only `request_mod_menu(id)` entry would mean “request the core menu,” not “navigate EP147 to SOURCE.” This name is illustrative; it is absent from the current SDK. Use the existing [size-gated ABI convention and AZ_HAS](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/azmod-mod.h#L185-L194), append after the current last field, update both SDK and core headers, and set a caller's `min_core` to the eventual release providing it. On older cores the caller must report unavailable or keep an explicitly separate legacy behavior.

For a first version, accept calls only on the overlay/UI thread (surface callbacks and tick already run there); enqueue a small core-owned request for a defined transition boundary. Use [cm_self](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/community.c#L1095-L1126) ownership checks, also require a currently loaded caller, and revalidate it when draining. Calls from frame/audio filters are refused. The existing [post_ui queue](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/sdk_ui.c#L54-L86) demonstrates bounded handoff and stopped-owner rejection, but can only invoke a mod's own function; it is not an existing menu service.

Proposed outcomes must distinguish queued, already open, and refused. Queued is not proof that a window appeared. Coalesce repeated requests and preserve the current page when already open. Do not queue behind another modal, another surface's knob ownership, reload or handoff. Initially admit only a stable waveform context with no native editing/modal view; revalidate before applying, and let an intervening native navigation event cancel the request. Do not leave a stale request waiting to open later. Exact admission checks still require implementation and tests, rather than assuming the coarse SDK view proves every native modal is absent.

## Required state and input changes

Introduce an explicit menu origin, such as `SOURCE_ROW` versus `DIRECT_DECK`, independently of the two-column layout and submenu state. The following paths must use that origin consistently.

The current “full-screen” menu is actually `(0,70,1280,625)` on a 1280×800 panel: [geometry](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/menu_full.c#L16-L21) and [dock dimensions](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/menu_layout.c#L12-L26). SOURCE's exposed strips cannot automatically be assumed safe over waveform controls. A narrow first direct-mode design should make the whole panel an opaque, input-owning core window while keeping existing menu controls at their established coordinates. Its unused bands consume touches; hardware performance controls remain unaffected. This is a proposed geometry policy requiring visual and touch testing, not present behavior. Preserve the SOURCE layout unchanged.

SDK [view classification already prioritizes MENU](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/sdk_surface_logic.h#L29-L45), so DECK-only surfaces can hide without falsifying the underlying screen. Core [stats readouts](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/mod_menu_overlay.c#L2281-L2288) currently depend only on waveform visibility and are placed after the menu: they need a menu-closed gate. Audit other windows and retain confirmation-dialog stacking above the menu. Opening/closing during an initiating touch must preserve complete press/release ownership; the current SDK emits DOWN and TAP on press and UP later ([dispatch](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/sdk_surface.c#L617-L641)).

Native-view monitoring also needs an explicit direct-mode policy. [Waveform detection](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/mod_menu_overlay.c#L315-L327) uses recent painting; loss of fresh paint while covered is not sufficient evidence that EP147 navigated away. Conversely, bypassing the SOURCE gate must not leave the menu covering a real native screen change. Existing [Browse/Search visibility hooks](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/azmod.c#L1885-L1904) and physical screen-button handoffs provide part of that evidence, but [ov_on_browse_view](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/mod_menu_overlay.c#L931-L947) currently clears visibility without closing the menu itself. SHORTCUT is byte 33 bit 0x10, outside the byte-32 handler; its existing [hook is diagnostic](https://github.com/Kyle-Hosman/xdj-az-mods/blob/3e0c5cb010454228f4ee63226b60d060494eeaae/src/azmod/source_list_entry.c#L781-L845). Cover actual navigation, not only SOURCE/BROWSE. Do not sample covered title/tab pixels as the native screen; retain native mode observations and refresh screen-dependent overlays on close.

## Required validation before calling this a working service

1. **ABI/request lifecycle:** old short API table, unavailable entry, wrong caller, frame-thread call, disabled owner, duplicate requests, queue saturation, request followed by native navigation, existing menu/page preserved. Opening with zero mixer callbacks must still reach a painted core menu.
2. **Origin-state tests:** direct open with `source_visible=0`, `want=0`; stale SOURCE handoffs and hidden list refreshes; direct close leaves native source selection unchanged; existing SOURCE preview/focus/pins remain unchanged. Exercise both event orderings around the transition boundary.
3. **Native input:** long-held BACK/click, rapid repeated BACK, knob movement and counter wrap, closure during movement, watchdog stall, simultaneous navigation and LOAD, invalid CRC frames. Check exact native frame bytes and no accumulated knob jump after close, not just menu callbacks.
4. **Visibility/touch:** actual 2 DECK, 2/4 and 4 DECK emulator screens; menu controls, drags with missing motion/release, initiating finger still down, top/bottom bands, stats/community surfaces, confirm dialog, native screen changes, and paint starvation under an opaque window. Verify return to the original view without synthetic SOURCE input or track/settings changes caused by opening.
5. **Separate core validation:** compile and existing upstream menu/input/SDK tests, then an emulator core with preserved rollback. Physical validation remains a deliberate later step away from practice. Passing the current callback-gap experiment does not validate any of these new transitions.

The main unresolved implementation question is safe native knob handback without SOURCE-row compensation, followed by complete native-view cancellation while the waveform is occluded. The source establishes a plausible core route; it does not justify shipping a flag-only shortcut.
